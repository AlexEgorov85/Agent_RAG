# Spec Delta

## Purpose

Превращает каждый PDF-отчёт Сбербанка в детерминированный, воспроизводимый JSON-артефакт
типизированных элементов (Title, NarrativeText, Table, Image, ...) с полными метаданными
(страница, год, sha256 источника). Является единственным слоем, к которому
structure/chunk/graph этапы обращаются за «сырём» данных — прямые вызовы Unstructured
в других модулях запрещены.

## ADDED Requirements

### Requirement: Детерминированное извлечение элементов

Система SHALL извлекать из каждого PDF-отчёта все типизированные элементы Unstructured
при стратегии `hi_res` и OCR-языках `rus`+`eng`, сохраняя для каждого элемента тип,
текст, номер страницы (1-based по `coordinates`) и `category_depth` для `Title`.

#### Scenario: Извлечение страниц отчёта 2015

- **WHEN** парсер применяется к `data/raw/Копия Сбер 2015.pdf` на страницах 1–3 со стратегией `hi_res`
- **THEN** извлекается ≥1000 элементов со всеми типами `Title`, `NarrativeText`, `Table`, `Image`
- **AND** каждому элементу присвоен валидный `page` в диапазоне `[1..3]`

#### Scenario: Заголовки распознаны по-русски

- **WHEN** элемент страниц обложки отчёта обработан
- **THEN** среди элементов есть `Title` с текстом «ГОДОВОЙ ОТЧЕТ» без гаражных OCR-мусорных символов

### Requirement: Стабильная идентификация элементов и документа

Система SHALL присваивать каждому элементу `element_id` вида `{doc_id}:{пятизначный индекс}`,
стабильный при повторном парсинге одного и того же файла, и вычислять `doc_id` из имени
файла по шаблону `sber_{год}`, где год — последняя 4-цифровая группа в имени файла.

#### Scenario: Именование doc_id

- **WHEN** парсится файл `Копия Сбер 2015.pdf`
- **THEN** `doc_id` равен `sber_2015`, а первый элемент получает `element_id = sber_2015:00000`

#### Scenario: Стабильность element_id

- **WHEN** один и тот же PDF парсится повторно из одного чек-XXXX без изменений
- **THEN** полученные `element_id` полностью совпадают с предыдущим прогон по позициям индексов

### Requirement: Полные метаданные артефакта

Система SHALL сохранять для каждого артефакта статистику: `source_url`, `source_sha256`,
год, число страниц, число элементов, counters по типам, время парсинга, стратегию,
OCR-языки и версию Unstructured — в `{doc_id}_stats.json` рядом с элементами.

#### Scenario: Статистика соответствует факту

- **WHEN** артефакт создан
- **THEN** `n_pages` совпадает с реальным числом страниц PDF, а сумма значений `by_type` равну `n_elements`

#### Scenario: sha256 источника

- **WHEN** артефакт создан и файл PDF не изменён
- **THEN** повторное вычисление SHA-256 файла совпадает с `source_sha256` артефакта

### Requirement: Фильтр мелких изображений

Система SHALL сохранять `image_b64` только для изображений площадью не менее 200×200 px
и SHALL записывать `image_b64 = null` для остальных изображений.

#### Scenario: Иконки не попадают в артефакт как base64

- **WHEN** на странице есть иконка размером 40×40 px и график 800×600 px
- **THEN** для иконки `image_b64 = null`, для графика — base64-строка; оба элемента сохранены

### Requirement: Батчевый парсинг с resume

Система SHALL парсить PDF батчами фиксированного числа страниц (типово 20) и SHALL
пропускать уже успешно спарсенный файл, если в `data/elements/` существует
`{doc_id}_stats.json` с совпадающим `source_sha256`.

#### Scenario: Повторный запуск ничего не пересоздаёт

- **WHEN** `parse_all` запускается повторно на полностью спарсенном каталоге `data/raw`
- **THEN** новые JSON-артефакты не создаются, runtime почти мгновенный (< 5 с)

#### Scenario: Спарсенный файл пропускается, новый обрабатывается

- **WHEN** каталог содержит 9 PDF, из которых спарсены 8
- **THEN** обрабатывается только недостающие, остальные пропущены без ошибок

### Requirement: Реакция на изменение источника

Система SHALL при изменении `source_sha256` спарсенного PDF выполнить полный пере-парс
и SHALL сохранить предыдущий артефакт в `data/elements/backup/`.

#### Scenario: PDF подменили

- **WHEN** содержимое файла `Копия Сбер 2023.pdf` меняется после успешного парсинга
- **THEN** повторный запуск пере-парсит его, а старые элементы уходят в `backup/`

### Requirement: Проверка среды выполнения OCR

Система SHALL перед парсингом со стратегией `hi_res` проверить доступность tesseract
в PATH, наличие файла `{lang}.traineddata` для каждого запрошенного языка в `TESSDATA_PREFIX`
и SHALL завершиться с понятной ошибкой и инструкцией по установке при нарушении любой из них.

#### Scenario: Tesseract отсутствует

- **WHEN** tesseract не найден в PATH
- **THEN** парсер завершается с ошибкой, содержащим шаги установки (winget/UB-Mannheim), до обращения к Unstructured

#### Scenario: Русская языковая модель отсутствует

- **WHEN** в `TESSDATA_PREFIX` нет `rus.traineddata`, а OCR-языки включают `rus`
- **THEN** парсер завершается явно с упоминанием отсутствующего файла, а не молча использует английский

### Requirement: Устойчивость к сбоям батча

Система SHALL при ошибке обработки одного батча страниц повторить его один раз,
продолжить следующие батчи при повторном сбое и SHALL сообщить в финальном отчёте канонично
не спарсенные диапазоны страниц с номерами страниц.

#### Scenario: Сбой одного батча

- **WHEN** батч страниц 121–140 падает дважды, а остальные батчи успешны
- **THEN** артефакт создаётся с элементами остальных батчей, а список пропущенных страниц `[121..140]` включён в лог и в статистику

### Requirement: CLI и режимы запуска

Система SHALL предоставлять CLI `python -m src.ingestion.pdf_parser` с режимами
один файл (`--pdf`), все файлы (`--all`), сводная статистика (`--stats`),
быстрое превью (`--fast-preview` — стратегия `fast`, без OCR) и smoke (`--smoke`),
где приоритет аргументов выше env-конфигурации.

#### Scenario: Превью отдельного файла

- **WHEN** вызов `--pdf "data/raw/Копия Сбер 2023.pdf" --fast-preview`
- **THEN** работает стратегия `fast`, OCR не задействован, печатьется краткая метаданные без создания артефактов

#### Scenario: Сводная статистика корпуса

- **WHEN** вызов `--stats`
- **THEN** печатаются `doc_id`, число страниц, элементов и время парсинга для каждого спарсенного файла
