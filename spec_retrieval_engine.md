# Спецификация retrieval и RAG engine

**Версия:** 1.0
**Статус:** целевой контракт; retrieval/engine ещё предстоит реализовать.
**Связанные документы:** [spec_target.md](spec_target.md), [spec_graph.md](spec_graph.md)

## 1. Назначение

Превратить пользовательский вопрос в ограниченный retrieval plan, найти релевантные
chunks, собрать компактный контекст и сформировать ответ с точными citations либо
корректно отказаться. Retrieval должен быть полезен без Graph Store; граф подключается
как дополнительный источник кандидатов.

## 2. API слоя

Публичный интерфейс:

```python
class RAGEngine:
    def ask(
        self,
        query: str,
        *,
        filters: SearchFilters | None = None,
        conversation_id: str | None = None,
    ) -> Answer: ...

    def retrieve(
        self, query: str, *, filters: SearchFilters | None = None
    ) -> RetrievalResult: ...
```

Результаты `retrieve()` не вызывают генерацию и удобны для тестирования/eval.
Внешние API-клиенты, embedder, индексы и graph retriever передаются зависимостями при
сборке engine; конструктор не читает глобальные переменные и не строит индексы сам.

### 2.1. SearchFilters

```text
years: set[int] | None
year_from: int | None
year_to: int | None
report_periods: set[str] | None
issuers: set[str] | None
kinds: set[str] | None
section_path_prefix: str | None
breadcrumb_contains: str | None
max_section_level: int | None
allowed_doc_ids: set[str] | None
```

Явные ограничения пользователя имеют приоритет над догадкой router. Фильтры должны
валидироваться: пересекающиеся годы нормализуются, `year_from > year_to` — ошибка,
неизвестный `doc_id` даёт пустой результат с диагностикой.

## 3. Router и QueryPlan

Router возвращает Pydantic-модель:

```text
intent: factoid | structural | temporal | multi_hop
years: list[int]
year_from: int | None
year_to: int | None
section_filter: str | None
entities: list[str]
needs_rewriting: bool
needs_graph: bool
answer_mode: concise | comparison | outline
```

Требования:

- Structured output валидируется. Невалидный/недоступный ответ router заменяется
  безопасным планом `factoid` без структурных ограничений и graph, но сохраняет
  явные фильтры пользователя.
- Router не выдумывает годы и не преобразует запрос «последние годы» в годы за пределами
  корпуса. Период `2021` помечается отсутствующим.
- `section_filter` должен разрешаться в существующий раздел или нормализованное имя;
  при неуверенном разрешении нельзя молча сужать выдачу до пустого набора.
- `needs_graph` — рекомендация, не гарантия наличия графового результата.
- Router не генерирует факты ответа.

## 4. Retrieval pipeline

Порядок выполнения:

1. Нормализовать запрос, объединить явные фильтры UI/API и результат router.
2. Применить eligibility к corpus candidates **до top-k**: годы, issuer, doc_id, kind,
   структурные условия.
3. При `needs_rewriting=True` получить максимум 2 перефраза. Перефраз не должен добавлять
   новые суммы, даты, компании или факты. Ошибка rewrite использует исходный запрос.
4. Выполнить dense и BM25 поиск по каждой формулировке, каждый возвращает не более 20
   кандидатов. Dense использует query-prefix, совместимый с выбранной embedding-моделью.
5. При `needs_graph=True` получить ограниченный список связанных chunks из
   `graph_retriever`; graph-результаты включаются в fusion с отдельным ranking list.
6. Слить ranking lists методом RRF (`constant=60`); дедупликация по `chunk_id`, tie
   сохраняет исходный порядок. Если в текущем API RRF есть аргумент `k` для длины
   выдачи, он не должен смешиваться с `constant`.
7. Передать до 10 уникальных кандидатов на LLM reranker. Баллы `0..3`; невалидный JSON
   — один повтор, затем fallback на порядок RRF. Reranker не может добавлять chunks.
8. Вернуть до 5 chunks. Хранить source score, rank, retrieval channel, rerank score и
   применённые фильтры для диагностики.

Настройки `CANDIDATES=20`, `RERANK_POOL=10`, `TOP_K=5`, `RRF_CONSTANT=60` вынести в
конфигурацию с этими значениями по умолчанию. Изменение значений отражается в eval
metadata.

### 4.1. Структурная eligibility

- `section_path_prefix` — сравнение по границе пути, а не обычный небезопасный prefix
  (`"Риск"` не должен совпадать с `"Риск-менеджмент"` без заданного правила).
- `breadcrumb_contains` сравнивается по нормализованным названиям сегментов.
- При неоднозначном совпадении нескольких разделов router сохраняет запрос широким,
  а UI показывает выбранное ограничение пользователю.
- Доля чанков без `section_path` измеряется корпусной проверкой. Если фильтр не может
  быть применён из-за отсутствия метаданных, возвращается warning, а не ложный нулевой
  ответ.

### 4.2. Временные запросы

Для периода строится множество доступных лет. Недостающие годы возвращаются отдельно
в `missing_years`. Retrieval выполняется только по существующим документам.
Генератор обязан:

- привязывать каждое числовое значение к году/периоду и цитате;
- не переносить факт из соседнего года;
- отличать «документ отсутствует» от «показатель не найден в документе»;
- предупреждать о несопоставимом issuer, в частности о 2015 (БПС-Сбербанк).

## 5. Context packing

`pack_context(hits, max_chars=16000)` упаковывает максимум заданного бюджета. Для каждого
чанка передаются: `chunk_id`, `doc_id`, год, issuer, PDF page, printed page label,
section path, kind, text и HTML таблицы при наличии.

- Чанк целиком включается либо пропускается; текст не обрезается посередине цитаты.
- HTML таблицы не отделяется от текста, которому он соответствует.
- Повтор одного `chunk_id` включается один раз.
- Упаковщик возвращает также manifest включённых/пропущенных chunks.
- Размер budget и его фактическое использование логируются.

## 6. Answer schema и генерация

Схема ответа определена в `spec_target.md` §5.2. Внутренняя Pydantic-модель должна
отклонять:

- `status` вне `answer|abstain`;
- citation с неизвестным `chunk_id`;
- citation на chunk, не включённый в context manifest;
- невалидные типы страниц/годов;
- `answer` без citations, если он содержит утверждение о содержимом отчётов.

`facts` — список структурированных утверждений, например:

```json
{
  "claim": "Чистая прибыль составила ...",
  "value": "…",
  "unit": "млрд руб.",
  "period": "2023",
  "chunk_id": "…"
}
```

`facts` может быть пустым для качественных вопросов. Любой факт из `facts` ссылается на
один или более возвращённых citations. Промпт запрещает смешивать годы и подставлять
внешние знания как факт из отчёта.

Переход в `abstain` обязателен, если:

- retrieval пустой после фильтрации;
- вопрос касается отсутствующего года, и данных соседних годов недостаточно для ответа;
- кандидаты не подтверждают центральное утверждение;
- citations/ответ не прошли schema validation даже после одного repair-повтора.

Отказ должен быть информативным, например «Отчёт за 2021 год в корпусе отсутствует»,
а не придумывать значение.

## 7. Fallback, ошибки и наблюдаемость

| Сбой | Поведение |
|---|---|
| Router API/JSON | План factoid + явные фильтры |
| Rewrite API | Исходный запрос |
| Dense API | BM25; warning в результате |
| BM25 пуст/не готов | Dense; warning в результате |
| Reranker API/JSON | Порядок RRF |
| Graph index отсутствует | Hybrid без graph |
| Generation API/JSON | Возвращается контролируемая ошибка или abstain; неподтверждённый ответ запрещён |

Каждый `RetrievalResult` содержит `query_plan`, effective filters, кандидатов с оценками,
`missing_years`, warnings и timings. Логи содержат `request_id`, этапы и длительность,
но не API keys.

## 8. Тесты и критерии приёмки

Unit-тесты обязательны для router fallback, фильтра до top-k, нормализации секций, RRF
дедупликации/tie, reranker-ошибок, budget packing, citation validation и abstain.
Интеграционные тесты используют fake embedder/LLM и не требуют внешней сети.

Функциональные тест-кейсы:

1. Факт из одного отчёта возвращается с правильным `chunk_id` и страницей.
2. Структурный фильтр не возвращает чанки из другого раздела.
3. Запрос периода 2020–2024 сообщает о пропуске 2021 и не приписывает соседнее значение.
4. «Сравни 2015 и 2023» явно сигнализирует о разных issuer.
5. Вопрос вне корпуса даёт abstain без citations.
6. Сбой graph/reranker не блокирует baseline retrieval.

Quality gates задаются по eval-профилю в `spec_ui_eval.md`; unit-тесты не заменяют
измерение качества на размеченном датасете.
